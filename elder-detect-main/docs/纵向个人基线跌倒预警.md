# 纵向个人基线跌倒预警

## 功能定位

该模块在现有实时跌倒检测之外，持续记录同一老人的步态和姿态摘要，使用14个有效观测日建立个人正常基线，并监测之后的偏离、趋势和持续时间。

当前仓库没有真实的长期随访和跌倒日期数据，因此系统默认输出个人偏离指数，不生成虚构概率。只有同时加载已完成独立验证并标记为 `calibrated=true` 的7天和30天 Landmark Cox 模型后，`risk_7d` 和 `risk_30d` 才会出现数值。

## 方法与文献依据

| 项目实现 | 依据 | 适用范围 |
|---|---|---|
| 前14个有效日建立个人基线 | Mehdizadeh 等在自然环境记录两周步态基线 | 个人中心值和正常波动范围 |
| eMOS 稳定性思路与近期跌倒史 | Mehdizadeh 等发现估计稳定裕度和跌倒史可预测距下一次跌倒时间 | 本项目使用 `emos_proxy`，明确标注为单目代理量 |
| 7天和30天预测窗口 | 同一研究用 Cox 模型输出7天、30天无跌倒生存概率；AUROC 分别为0.80和0.67 | 项目固定的两个预测窗口 |
| 持续更新的步态特征 | Adeli 等用环境视觉步态、临床评估和用药预测未来4周跌倒，AUROC 0.762 | 支撑日级滚动观测和约30天窗口 |
| Cox 比例风险模型 | Cox 1972 | 有标签后的条件生存概率 |
| Landmark 动态预测 | van Houwelingen 2007 | 把每个有效观测日作为新预测时点 |
| 中位数与 MAD 稳健标准化 | Iglewicz 与 Hoaglin 的稳健离群值方法 | 减少偶发姿态错误和极端值影响 |

2. Adeli V, et al. Ambient Monitoring of Gait and Machine Learning Models for Dynamic and Short-Term Falls Risk Assessment in People With Dementia. DOI: `10.1109/JBHI.2023.3267039`。
3. Cox DR. Regression Models and Life-Tables. DOI: `10.1111/j.2517-6161.1972.tb00899.x`。

## 输出含义

`deviation_index` 位于0到1之间，是多项稳健 z 分数的截断均方根距离归一化值。它只回答“当前步态姿态与本人基线相差多远”，不等于跌倒概率。

状态含义：

- `insufficient_quality`：本次数据质量不足，不参与基线和预测。
- `collecting`：尚未收集到14个有效日。
- `baseline_ready`：已建立基线，当前结果是统计偏离监测。
- `calibration_required`：连续3个有效观测日超过3个稳健标准差，建议人工复核，但没有经校准的跌倒概率。
- `calibrated`：已加载校准模型，可输出未来7天和30天累计跌倒概率。

24小时和72小时不在当前输出中，因为上述研究没有直接验证这两个窗口，仓库也没有相应事件标签。

启用 DS-PCD（`--detector ds_pcd` 或 `both`）时，结果额外包含 `ds_pcd` 子对象：`status`、`z`、`T`、`p_value`、`q`、`cusum`、`top_contributors`、`mask`、`precision_mode`、`baseline_end`、`cusum_resets_to_as_of`、`alarm` 等。`T` 是方向先验约束的平方统计量，`q` 是个人零分布上尾概率的正态分数，`C` 是 `C_{t}=max(0,C_{t-1}+q_t-0.5)` 的累计值；相邻有效观测跨过 7 个日历日时 `C` 重置，个人基线保留。`alarm` 只在明确标注的仿真零假设下按目标误报率标定阈值后才展示，不是真实 30 天误报率。

## 无模型运行流程

每天导入一次观测：

```powershell
python scripts/collect_longitudinal.py `
  --input data/daily/2026-11-01.json `
  --person-id elder_001 `
  --observed-at 2026-11-01T08:00:00 `
  --profile-dir profiles
```

也可以读取包含 `landmarks`、`timestamps` 和 `visibility` 的姿态缓存：

```powershell
python scripts/collect_longitudinal.py `
  --input pose_cache/example.npz `
  --person-id elder_001 `
  --observed-at 2026-11-01 `
  --profile-dir profiles
```

收集至少14个有效日后建立基线：

```powershell
python scripts/build_personal_baseline.py `
  --person-id elder_001 `
  --profile-dir profiles
```

计算最新偏离：

```powershell
python scripts/predict_future_fall.py `
  --person-id elder_001 `
  --profile-dir profiles
```

结果保存在：

```text
profiles/elder_001/observations.jsonl
profiles/elder_001/baseline.json
profiles/elder_001/latest_risk.json
```

## 训练数据格式

当取得真实纵向随访数据后，训练 CSV 每行代表一个 Landmark 预测时点：

```text
person_id,landmark_date,next_fall_date,censor_date,distance,trend_7d,persistent_deviation_days
elder_001,2026-01-15,2026-01-20,2026-06-30,3.2,0.18,3
elder_002,2026-01-15,,2026-06-30,0.7,-0.02,0
```

训练命令：

```powershell
python scripts/train_landmark_cox.py `
  --data longitudinal_training.csv `
  --features distance trend_7d persistent_deviation_days `
  --out-dir model/longitudinal/cox_v1
```

默认生成的模型为 `calibrated=false`，即使能够拟合也不能输出概率。完成独立验证后，准备验证指标 JSON：

```json
{
  "independent_validation": true,
  "horizons": {
    "7": {"auroc": 0.78, "calibration_slope": 0.96},
    "30": {"auroc": 0.70, "calibration_slope": 0.91}
  }
}
```

这些数值必须来自真实独立验证，示例仅说明文件结构。带验证指标重新导出：

```powershell
python scripts/train_landmark_cox.py `
  --data longitudinal_training.csv `
  --features distance trend_7d persistent_deviation_days `
  --out-dir model/longitudinal/cox_v1 `
  --validation-metrics validation_metrics.json `
  --mark-calibrated
```

使用校准模型预测：

```powershell
python scripts/predict_future_fall.py `
  --person-id elder_001 `
  --profile-dir profiles `
  --model-7d model/longitudinal/cox_v1/risk_7d.json `
  --model-30d model/longitudinal/cox_v1/risk_30d.json
```

## 与现有融合输出连接

纵向风险不会改变现有 B/E/P/I 风险。需要在同一个汇总 JSON 中展示时，显式传入：

```powershell
python scripts/fuse_risk.py `
  --b-risk 0.1 `
  --future-risk-json profiles/elder_001/latest_risk.json
```

新结果只写入顶层 `future_risk` 字段，现有 `aggregate` 和 `per_video` 结构保持不变。

## 数据质量与限制

默认最低质量要求为150个有效帧、20个有效步、10秒有效步行时间、0.5平均置信度和80%核心特征覆盖率。这些是工程门控值，不是临床诊断阈值。

单目视觉的尺度和视角会影响空间指标，因此 `gait_speed_proxy` 和 `emos_proxy` 必须在固定摄像机条件下用于同一个人的纵向比较。部署环境、摄像机位置或姿态后端改变后应重新建立基线。

## DS-PCD 基线与命令

```powershell
# 采集姿态时估计会话标准误（可选）
python scripts/collect_longitudinal.py --input day.npz --person-id elder_001 --observed-at 2026-11-20 --with-uncertainty

# 同时建立 RMS 与 DS-PCD 基线（DS-PCD 使用与 RMS 相同的 14 个基线日）
python scripts/build_personal_baseline.py --person-id elder_001 --detector both

# 按预测日同时输出两套指标
python scripts/predict_future_fall.py --person-id elder_001 --detector both --as-of 2026-12-01
```

DS-PCD 的参考漂移固定为 0.5，个人基线为最早 14 个合格观测日（剔除 |稳健 z|>4 的日期）。会话精度只覆盖“有限步数/帧数造成的抽样不确定性”，不覆盖传感器或机位系统偏差；段数不足时使用同人合并标准差回退。真实连续监测的误报率尚未验证，不能把仿真阈值当作部署阈值。

## 阶段 7：研究协变量与研究接口

服务结果新增以下只读字段，旧字段保持不变：

- `research_covariates`：`rms_distance`（与 `distance` 同值）、`cusum`（研究 B 模型所需的 DS-PCD 累计值）、`distance`、`deviation_index`、`trend_7d`、`persistent_deviation_days`。
- `research_covariate_status`：每个协变量是 `available` 还是 `missing:<状态>`（如 `no_baseline`、`ds_pcd_disabled`、`config_mismatch`）。
- `provenance`：`modality`、`population`、`feature_version`、`detector`、`precision_mode`、DS-PCD 配置指纹、基线与 DS-PCD 基线版本、来源与预测日。
- `valid_day_counts`：`n_valid_days`（含预测日）与 `n_valid_days_before_landmark`（严格早于）。

研究模型只用于离线核查：

```python
from longitudinal.research import research_prediction
prediction = research_prediction(result, artifact)  # calibrated=False, research_only=True
```

穿戴设备日输入的对应关系：

| 服务字段 | CVS 日表字段 | 单位 |
|---|---|---|
| `walking_speed_m_s` | `ws_30_avg_d` | m/s（≥30 秒步行段） |
| `cadence_spm` | `cadence_all_avg_d` | steps/min |
| `stride_duration_s` | `strdur_all_avg_d` | s |
| `feature_se` | 阶段 5 逐日冻结 `se_*` | 与特征同单位 |

示例：`python scripts/demo_longitudinal_stage7.py --person 1049 --landmark 2023-04-22`。研究折模型即使能算出数值，也不得通过服务概率接口输出；未校准模型的 `risk_7d/risk_30d` 保持为空。视频入口继续使用其自身 11 项特征和会话精度，Mobilise-D 模型不跨模态复用。

## 阶段 8：模型输入契约

研究模型可带版本化的 `input_contract`（schema v1），记录模态、特征定义/版本、适用人群、分数版本、RMS 配置指纹、DS-PCD 配置指纹与精度模式。示例和状态表见 `output/ds_pcd_mobilise/stage8/20261114-contract-v2/CONTRACT.md`。

```python
from longitudinal.research import research_prediction
prediction = research_prediction(result, artifact)
# status: ok | contract_missing | contract_invalid | missing_provenance |
#         modality_mismatch | feature_version_mismatch | population_mismatch |
#         score_version_mismatch | rms_config_mismatch | missing_covariates |
#         invalid_covariates | precision_mode_mismatch | ds_pcd_config_mismatch
```

- 非 `ok` 时 `risk=None`；`calibrated=false` 和 `research_only=true` 保持不变。
- 服务入口对声明契约的模型使用同一匹配规则：不匹配时状态为 `model_input_mismatch`，7/30 天概率为空，`model_input_status` 给出每个窗口的具体状态。无契约旧模型保留 `legacy_no_contract` 兼容路径。
- 旧模型（无契约）在新的正常研究入口返回 `contract_missing`；需要使用阶段 8 导出的带契约副本，或为旧模型补契约。
- `research_covariate_status["covariates"]` 现在覆盖 `rms_distance`、`cusum`、`distance`、`deviation_index`、`trend_7d`、`persistent_deviation_days`，原有顶层 `rms_distance`/`cusum` 字段保留。
- A 的指纹只覆盖 RMS 距离依赖（排除 `persistent_*` 与 `timezone`）；B 的 DS-PCD 指纹只覆盖 C 计算（排除 `bootstrap_samples`、`min_bouts`）。`population` 随模型保存，但不作为硬性匹配条件。
- 导出命令：`python scripts/export_mobilise_stage8_models.py`；当前带契约副本和来源哈希在 `output/ds_pcd_mobilise/stage8/20261114-contract-v2/`（v1 保留为历史）。
- 契约只验证输入语义，不替代校准或外部验证；阶段 6 模型仍为 `calibrated=false`。
