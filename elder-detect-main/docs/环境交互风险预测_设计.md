# 环境交互风险预测 · 设计文档

> 版本：v0 设计稿（2026-07-16）
> 状态：Phase-1 实现中
> 关联：`scripts/fuse_risk.py`、`model/env/env_risk_model.py`、`features/gait.py`、`pose/keypoint.py`

## 1. 目标

把环境风险从「障碍物存在」（静态、必然误报）升级为「碰撞即将发生」（动态、可前瞻预测）。
系统不再"看着人摔倒"，而是分析老人运动轨迹是否正以一种"无察觉、不避让"的态势冲向环境中的物理危险点，从而提前 1~2 秒预警。

## 2. 核心公式
    
环境交互风险逐帧分解：

```
R_env_interaction(t) = E_spatial(t) × I(t) × (1 − C(t))
```

| 分量 | 含义 | 粒度 | 来源 |
|------|------|------|------|
| `E_spatial(t)` | 环境危险点的空间分布（掩码） | 逐帧 | 新建 `EnvMaskBuilder` |
| `I(t)` | 干涉系数 = 预测区域与环境掩码的重叠度 | 逐帧 | 新建 `IntentGate` |
| `C(t)` | 代偿系数（是否在避让） | 逐帧 | Phase-3，v0 恒为 0 |

实际进融合层的是 `E_effective(t) = E_semantic × I(t)`（见 §6）。

## 3. 与现有系统的分层关系（不替换 VLM，分层）

现有 `E = HOME FAST` 视频级标量（语义层）。新增的是逐帧空间层。两者分层并存：

| 层 | 来源 | 粒度 | 回答的问题 | 去向 |
|----|------|------|-----------|------|
| `E_semantic`（现有，保留） | VLM → HOME FAST 25题 | 视频级标量 | "这个家整体隐患多大" | `risk_long` + 阈值上下文 |
| `E_spatial`（新增） | 背景差分 + HSV / VLM粗掩码 | 逐帧掩码 | "此刻脚下哪里有危险点" | `I` 门控 |

**关键**：门控用的是 `E_spatial`；`E_semantic` 继续做长期分。不替换 VLM，保留语义层可解释性（"这是电线还是水渍"仍可追溯）。

## 4. 三个已知风险及解法

### 4.1 背景差分被老人自身污染
- **问题**：老人是画面里的"新增物体"，全画面背景差分会把人一起检出。
- **解法**：不做全画面差分，**限定地面带状 ROI**（画面下方约 1/3，家居机位通用假设：地面在画面下方）+ **人脚挖孔**（用 pose 脚踝/脚跟关键点定位人脚，挖掉脚周围半径 r 的圆——人在那里不算"环境危险"）。

### 4.2 单目沿光轴失效
- **问题**：单目无深度，老人沿摄像头光轴方向走时，像素平面速度 ≈ 0，预测区域塌缩成一个点，`I` 在半数运动方向上失效。
- **解法**：用 `normalized_landmarks`（画面归一化坐标）的髋中心做 2D 速度矢量；当 |v|₂D 小但 `world_landmarks.z`（伪深度，相对髋中心）持续减小 → 判定"沿光轴接近"（正对镜头走来），把预测区域沿画面中心方向拉长。z 虽是伪深度，但**相对变化**有信号，能救回一半失效场景。

### 4.3 代偿检测循环依赖（最危险）
- **问题**：用来判定"已避障"的代偿信号（减速、步幅减小、重心后移）在论文3里本身就是跌倒前兆（stride↓、cadence 异常）。用跌倒前兆来"降低风险"= 漏报。
- **解法**：v0 不上线代偿（`C(t)≡0`）。Phase-3 先做离线实验区分"主动避障减速"（节奏稳、重心可控、头部转向障碍物）vs"失稳性步态紊乱"（节奏乱、重心晃、无头部转向），验证可分性后再决定上线。验证前阈值锁死 0.3/0.6 不动。

## 5. 三通道算法

### 通道 1：环境掩码 `E_spatial`（`features/env_mask.py`）

```
输入：视频帧 sequence + pose landmarks（脚踝位置，用于人脚挖孔）
流程：
  1. 地面带状 ROI = 画面下方 1/3
  2. 人脚挖孔：pose 脚跟(heel=29/30) 定位人脚 → ROI 内挖掉脚周围半径 r 的圆
  3. 双通道危险检测：
     - 静态新增物：MOG2 背景差分 → ROI 内 → 排除人脚区 → 形态学开运算去噪
     - 反光区（水渍）：HSV 空间 V 高(亮) + S 低(低饱和)
  4. 输出逐帧二值掩码 M(t)
```

**v0 简化**（Phase-1 骨架）：跳过差分，用 VLM hazard 标签做粗掩码——有 hazard 就在地面 ROI 下半部填 1。先验证 I 门控管道是否有效，再投入做差分精化。

### 通道 2：运动意图投影（`features/intent.py`）

```
输入：pose landmarks（髋中心 2D）+ world_landmarks（z 深度代理）
流程：
  1. 髋中心 2D 位置 p(t) = ((LEFT_HIP.x + RIGHT_HIP.x)/2, (LEFT_HIP.y + RIGHT_HIP.y)/2)  # 归一化坐标
  2. 2D 速度矢量 v(t) = (p(t) − p(t−k)) / Δt，k = INTENT_VEL_WINDOW 帧
  3. 预测落点 p_pred = p(t) + v(t) × INTENT_HORIZON
  4. 预测区域 Zone(t) = 椭圆（中心=p_pred，长轴沿 v 方向，短轴=步幅横向容差）
  5. 沿光轴兜底：若 |v|₂D < 阈值 且 world_z 持续减小 → 判定沿光轴接近，
     预测区域改为以 p(t) 为中心、沿画面中心方向拉长的椭圆
输出：Zone(t) 参数 {center, axes, angle}
```

### 通道 3：I 门控（`features/intent_gate.py`）

```
I(t) = 预测区域 Zone(t) 落在掩码 M(t) 内的像素占比 ∈ [0,1]
```

用"占比"而非 IoU：预测区域远小于掩码时，IoU 会因分母大而爆跳，占比更稳。无重叠 → I=0。

## 6. 融合层接入（`scripts/fuse_risk.py`）

现有融合（不改）：
```
risk_short = FUSE_W_B × B                      # B 独占短期
ctx = CTX_W_E × E + CTX_W_P × P                # E/P 只调阈值
θ_alarm = clamp(THR_ALARM_BASE − CTX_GAIN·ctx, FLOOR, BASE)
```

门控接入后（`--enable-gate` 开启）：
```
E_effective(t) = E_semantic × I(t)             # 逐帧，无碰撞 → E 归零
ctx(t) = CTX_W_E × E_effective(t) + CTX_W_P × P
θ_alarm(t) = clamp(THR_ALARM_BASE − CTX_GAIN·ctx(t), FLOOR, BASE)
```

**语义变化**：原"家里有隐患就一直敏感"→"只有真要撞上了才下调阈值提高敏感度"。这正治"老人离障碍物远但 E 仍激活"的误报。

`--enable-gate` 默认关，关闭时行为完全等价现有 pipeline（向后兼容）。

### 7.2 PoseResult 访问方式
- `result.get(BodyPart.LEFT_HIP)` → `Keypoint`，`x/y` 为 **MediaPipe 归一化坐标 [0,1]**（x 相对宽，y 相对高），`z` 为相对深度
- `result.get_world(BodyPart.LEFT_HIP)` → `Keypoint`，`x/y/z` 为**世界坐标（米）**，z 相对髋部中心
- `result.frame_width` / `result.frame_height`：原始帧像素尺寸（归一化坐标转像素用）
- `result.timestamp_ms`：帧时间戳（毫秒）

> 注意：`landmarks`（归一化2D）用于速度矢量；`world_landmarks.z`（米）用于深度代理兜底。二者不可混用。

## 11. 验证方法

`scripts/verify_intent_gate.py`：
- 跑 `test/` 视频对比 开/关 `--enable-gate` 的误报帧数与风险曲线
- 重点验证：老人离障碍物远（I≈0）时，`E` 不再激活报警 → 降误报
- 输出：对比表（开/关 alarm_frames）+ 逐视频明细 JSON

## 12. 已知限制（v0）

1. VLM 粗掩码无空间精度——整个地面 ROI 下半部统一标记，I 只能做"有无"级门控，不能定位具体危险点。v1 差分精化后改善。
2. 深度代理（`world_z`）是伪深度，沿光轴兜底是启发式，复杂场景（多人、遮挡）下不可靠。
3. 代偿未上线，"平稳步态+即将碰撞+无调整"的最高级预警暂不触发（v0 只做"碰撞预测"门控）。

### 13.2 关键设计修正（实现中发现）
**原方案缺陷**：预测区域用髋中心 (x,y) 外推，但环境掩码在地面 ROI（画面下方 1/3），髋部 y≈0.5 在画面中部，两者 y 范围不重叠 → I 恒 0。

**修正**：预测区域纵向锚定**脚下**（脚跟平均 y `foot_y`，`_foot_y()` 方法），横向用髋速度外推——"人走到哪脚踩到哪，环境交互点在脚下而非髋部"。修正后 I 在横向走+hazard 时达 0.6~1.0，无 hazard 时归零，门控生效。

### 13.3 冒烟测试结果（`temp/smoke_intent.py`）
1. 横向走 + hazard → I = 0.6~1.0 ✅
2. 无 hazard → I = 0（门控归零，**核心效果验证**）✅
3. 静止原地 + hazard → 不崩，I 合理 ✅
4. 沿光轴接近（|v| 小 + world_z 持续减小）→ `optical_axis_approach = 1` ✅

### 13.7 v1 纯算法掩码 + 视频端到端 demo（2026-07-16 完成）

用户决策（2026-07-16）：**运行时不调 VLM**，VLM 仅部署时一次性标定静态基线。废弃 v0 VLM 粗掩码（运行时依赖 VLM 标签）。

**VLM 离线标定**（`scripts/vlm_baseline_calibrate.py`）：方舟 Doubao 看场景首帧 → 输出 `ground_top_y` + 障碍物 bbox → `env_baselines/<scene>.json`。Subject.1_Fall_backwards 标定结果：ground_top_y=0.31，4 个固定障碍物（抽屉柜/电脑桌/边桌/塑料椅），confidence=0.94。

**bg_diff 纯算法掩码**（`features/env_mask.py` 重写加 bg_diff 模式）：
- MOG2 背景差分（检测新增物）+ HSV 反光（水渍：V>200 & S<60）+ 地面 ROI（VLM 基线 ground_top_y）+ 人脚挖孔（pose 脚跟）+ 合并 VLM 静态障碍物 bbox + 形态学开运算去噪
- `EnvMaskBuilder.from_baseline(json)` 加载 VLM 基线 → bg_diff 模式，运行时纯 OpenCV 不调 VLM
- 保留 vlm_coarse 模式向后兼容

**视频端到端 demo**（`demo/intent_gate_demo_video.py`）：
