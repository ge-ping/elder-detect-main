## 1. 架构决策（短期 / 长期 + 公式修正）

用户原公式笔误：`risk = a·risk_环境 + b·risk_环境 + c·risk_姿态`（写了两个环境）。经确认，修正与锁定如下：

- **环境信号来源** = **同摄像头场景理解**（复用现有视频帧，无新硬件 / 新数据采集）。
- **复合公式第三分量** = **risk_功能代理 / 健康**（骨架派生，非真实生理、非行为）：
  **`risk = a · risk_环境 + b · risk_功能代理 + c · risk_姿态`**
  > 注：`risk_功能代理` 由骨架特征算（步态/平衡/起立/疲劳），称"功能/生理**代理**"而非真实生理（报告 §3.3/§11.4 严谨要求）。
- **长短时映射**：
  - **短期（imminent，秒级报警）** = 姿态(即时) + 功能代理(即时) + 环境(即时：脚下/台阶/水渍)
  - **长期（background，天/周级监护分）** = 环境(静态：房间/光照/布局) + 步态趋势 + 个体基础(元数据)
- Phase-1 的 `RiskRegressor` 即 **`c · risk_姿态` 的短期即时分量**；Phase-2 在其上**加性**并入环境与健康。

## 2. 双输出概念架构

```
                        同摄像头视频帧
                       /                \
            Pose 分支 (Phase-1 已有)      Scene 分支 (Phase-2 新)
              │                            │
        RiskRegressor                EnvPerceive (感知层)
              │  risk_姿态 ∈[0,1]        │  env 属性 → risk_环境 ∈[0,1]
              │                            │   ├ 即时(脚下/台阶/水渍) → 短期
              │                            │   └ 静态(房间/光照/布局) → 长期
              │                            │
        gait_trend (姿态长窗聚合)       physio (元数据) → risk_生理 ∈[0,1]
              │                            │
   ┌──────────┴───────────┐            │
 短期 risk_short          长期 risk_long  │
 = w_posture·risk_姿态    = w_env_st·risk_环境(静态)
 + w_env_im·risk_环境(即时) + w_gait·gait_trend
 (≥ θ_alarm → 报警)       + w_physio·risk_生理
                            (→ 监护优先级分)
```

| 输出 | 喂入分量 | 时间窗 | 用途 | 触发 |
|------|----------|--------|------|------|
| **risk_short（报警）** | risk_姿态(即时) + risk_环境(即时) | 秒级（W=35≈1.4s） | 跌倒 imminent 报警 | ≥ θ_alarm |
| **risk_long（监护分）** | risk_环境(静态) + gait_trend + risk_生理 | 天 / 周级 | 高跌倒风险人群筛查 | 分档 |

> Phase-1 的 `RiskRegressor` 已覆盖 `risk_姿态`；`gait_trend` 可由同模型在更长窗口上滑动统计得到（复用，不新增模型）。**Phase-2 新增两块：`EnvRisk`（场景分支）与 `PhysioRisk`（元数据分支）**，二者都用**晚期分数融合**（匹配用户公式的加性），与现有模型解耦、可独立迭代。

## 4. ★ 环境风险模块 EnvRisk（本次落地目标）

**输入**：同摄像头帧（与 MediaPipe 抽帧共用，零新增数据）。现有 5 数据集背景已含环境信息（Le2i 居家 / UR-FALL 床边 / CAUCAFall 多房间 / UP-FALL 日常 / Pre-VFall 跌倒前活动），**但无任何环境标注** → 这是模块最大约束（见 §6 启动策略）。

**两层结构**：
1. **感知层（预训练，不从头训）**：从帧抽取可解释环境属性 ——
   - 房间类型 room_type（浴室 / 卧室 / 楼梯 / 走廊 / 客厅 …）
   - 地面材质 / 状态 floor（瓷砖 / 木 / 地毯 / 疑似湿滑）
   - 脚下障碍物 / 台阶 / 门槛（近场，喂短期）
   - 光照 level（过暗 / 眩光）
   - 布局拥挤度（远场，喂长期）
2. **风险映射层**：把属性 → `risk_环境 ∈ [0,1]`。三条路线对比 ——

| 路线 | 做法 | 标签需求 | 优劣 |
|------|------|----------|------|
| **R0 规则映射（v0 起步）** | 临床 / 常识危险度表（浴室→0.6、湿滑→0.8、地毯松散→0.5、过暗→0.4、清爽→0.05） | 零 | 可解释、秒出、可立刻融合；但粗、无数据驱动 |
| **R1 VLM API 直接标注（升级）** | 用多模态大模型(VLM API)对帧零样本直接打 hazard 分(0~1)+理由 → 直接映射成 `risk_环境`（**不训 ViT**） | 弱标签(VLM 生成) | 数据驱动、贴合分布；需 VLM API 调用（离线批标），无本地训练 |
| **R2 直接 VLM 推理（不推荐）** | 每帧问 VLM 出分 | 无 | 最省事但**非实时**、成本高，仅调试用 |

> **推荐路径**：先上 **R0** 立刻拿到第一个可融合的 `risk_环境`，验证双输出融合 pipeline；再视效果上 **R1** 用 VLM API 直接标注得到数据驱动的 `EnvRisk`（**不训 ViT**）。
>
> 📄 **EnvRisk v0（R0 规则）详细设计方案**：见同目录 **`envrisk_v0_design.md`**（已锁定：感知=数据集元标签、作用=仅推理/融合；含规则表、配置项、文件布局、验证与落地顺序）。状态：🔧 设计完成，待写代码。
>
> 📄 **EnvRisk R1（VLM API 直接标注，不训 ViT）详细设计方案**：见同目录 **`envrisk_r1_vlm_design.md`**（已锁定：直接=VLM API 零样本标注、不训 ViT、离线批标+缓存 sidecar、推理只读；含抽帧/Prompt/解析质控/映射/成本/文件布局/验证/落地）。状态：🔧 设计完成，前置=取回 5 数据集源视频 + API Key。

**即时 vs 静态拆分**：`env_即时` = 近场脚下（障碍 / 台阶 / 湿滑）→ 喂 `risk_short`；`env_静态` = 房间类型 / 光照 / 布局 → 喂 `risk_long`。

**输出 / 存储（隔离同 Phase-1 §4）**：每帧 `risk_环境` 存 sidecar `pose_cache/<name>.env_risk.npy`（不回写 npz）；窗口级聚合供融合。

## 5. 融合（晚期分数级，匹配用户公式）

```
risk_short = w_posture · risk_姿态 + w_env_im · risk_环境(即时)        # 报警，≥ θ_alarm
risk_long  = w_env_st · risk_环境(静态) + w_gait · gait_trend
           + w_physio · risk_生理                                   # 监护分，分档
# 用户总公式（概念分解）： risk = a·risk_环境 + b·risk_生理 + c·risk_姿态
```
- 加性融合 = 各分量独立出分再加权，**模块解耦**，任一分量可单独重训 / 替换（如 EnvRisk 从 R0 升 R1 不影响 PostureRisk）。
- 权重 a/b/c、短期 / 长期系数均为**可配置超参**，先拍初值（如短期 w_posture=0.6 / w_env_im=0.4；长期均分），后用验证集调。
